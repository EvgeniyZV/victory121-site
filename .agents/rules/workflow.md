# Правила работы над проектом Victory 121 (`victory121-site`)

Владелец работает над сайтом с **нескольких ноутбуков**. Любой `git push` в ветку `main` репозитория `https://github.com/EvgeniyZV/victory121-site.git` **сразу публикуется** на действующий сайт `https://victory121.kz/` (Plesk Git + webhook). Поэтому следующие правила обязательны в каждом разговоре.

## 1. В начале работы — проверить актуальность относительно GitHub
- Выполнить `git fetch origin` и `git status -sb` (при необходимости `git log --oneline HEAD..origin/main`).
- Если в `origin/main` есть новые коммиты (например, сделанные с другого ноутбука) или есть локальные незакоммиченные изменения — **сообщить владельцу и предложить синхронизацию** (`git pull --ff-only`). Не выполнять `pull`/`merge`/`rebase`/`stash`/`reset` без согласия, если это может затронуть локальные правки.

## 2. Все изменения — сначала локально, с показом результата
- Правки вносить только в локальной рабочей копии.
- Показывать результат владельцу до публикации: локальный предпросмотр `python -m http.server 8121 --bind 127.0.0.1` → `http://127.0.0.1:8121/`, скриншоты и/или `git diff`.

## 3. Без явного разрешения — ничего не отправлять и не публиковать
- **Запрещено без явного разрешения владельца в текущем разговоре:** `git push` (в любую ветку), `git push --force`, создание/удаление веток и тегов на GitHub, изменение настроек репозитория GitHub, любые загрузки файлов на сервер или в `victory121.kz`.
- Локальные коммиты допустимы только с согласия владельца; разрешение на коммит **не является** разрешением на `push`.
- `git push --dry-run` (проверка доступа, ничего не отправляет) — разрешён.

## 4. Перед отправкой — проверка конфликтов с другим ноутбуком
Непосредственно перед каждым одобренным `push`:
1. `git fetch origin`.
2. Убедиться, что `origin/main` не ушёл вперёд (`git status -sb`, `git log --oneline HEAD..origin/main`).
3. Если ушёл — остановиться, сообщить владельцу, какие коммиты и файлы пришли с другой машины, и предложить безопасную интеграцию (`git pull --rebase` или merge) с повторной локальной проверкой результата. Никогда не использовать `--force` для «решения» расхождения.
4. Отправлять только fast-forward изменения; после публикации проверить, что изменение появилось на `https://victory121.kz/`.

## 5. Plesk и автопубликация — не трогать без разрешения
- Не изменять настройки Plesk (`srv-plesk14.ps.kz`), Document Root, модуль Plesk Git, webhook, DNS, SSL, `.htaccess`-заголовки безопасности сервера и прочие настройки хостинга/автодеплоя без явного разрешения владельца.
- Папки `/new.victory121.kz`, `/httpdocs` и архив `/backup_new_victory121_kz_before_switch.zip` на сервере — не трогать.

## 6. Действие правил
Эти правила действуют во всех новых разговорах Antigravity по этому проекту наравне с `graphify.md`, `AGENTS.md` и `GEMINI.md`. При конфликте инструкций приоритет у запрета на публикацию без разрешения.
